# 项目 Agent 上下文与执行治理优化

## 结论

本次优化的目标不是单纯缩短上下文，而是让 Agent 获得准确、统一、按需且可验证的项目基础上下文。项目已从“在入口文件中持续堆叠说明”调整为“权威分层、语义路由、最小充分执行和确定性交付”。

最终形成以下稳定结果：

1. OpenSpec 负责项目行为和正式契约，`AGENTS.md` 只保留跨任务硬约束、路由和门禁。
2. Claude Code 与 Codex 共用同一份基础上下文，不再维护两套规则副本。
3. 详细规则、Skill、Change 和 Program 按任务语义加载，不进入常驻上下文。
4. Agent 以最小充分范围完成实施、验证和审查，提交阶段不重复收口工作。
5. 普通 Git 提交收敛为两个确定性批次，减少主 Agent 串行交互，并提供清晰的结构化结果。
6. 跨任务记忆检索属于系统级路由，不污染项目规则；同一逻辑任务只检索一次并复用结果。

## 最终上下文架构

| 层级 | 权威入口 | 职责 |
| --- | --- | --- |
| 项目行为与正式契约 | [OpenSpec specs](https://github.com/LuckyZen/WorldTourCasino/tree/classic_vegas_web_refactor/openspec/specs) | 定义项目当前应有的行为、领域规则和治理契约 |
| 常驻基础上下文 | [AGENTS.md](https://github.com/LuckyZen/WorldTourCasino/blob/classic_vegas_web_refactor/AGENTS.md) | 只保留跨任务硬约束、通用路由和硬门禁 |
| Claude Code 兼容入口 | [CLAUDE.md](https://github.com/LuckyZen/WorldTourCasino/blob/classic_vegas_web_refactor/CLAUDE.md) | 以符号链接复用 `AGENTS.md`，不保存独立内容 |
| 任务工作流 | [项目 Skills](https://github.com/LuckyZen/WorldTourCasino/tree/classic_vegas_web_refactor/.claude/skills) | 在命中特定任务时加载完整操作流程 |
| 专项参考 | [ai-rules](/../工程-工具/ai-rules) | 保存项目地图、脚本、工作区、文档等详细规则 |
| 在途工作 | OpenSpec Change / Program | 保存当前变更或长期项目的目标、设计、任务和验收状态 |

长期且庞杂的项目工作，例如 DH 浏览器渐进式资源 Program，只保留在对应 Program 工件中。它不是所有任务都必须携带的基础知识，因此不进入 `AGENTS.md`。

## 已完成的治理优化

### 1. 统一基础上下文

**完成内容**

- 将 `AGENTS.md` 确立为唯一常驻入口，并将默认中文、ES5、OpenSpec、收口和提交门禁集中到这里。
- 将 `CLAUDE.md` 改为指向 `AGENTS.md` 的符号链接。
- 将项目地图、Flavor、构建命令和专项细则移到按需参考文件。
- 为符号链接关系增加治理检查，防止两个入口再次分叉。

**优化成果**

- Claude Code 与 Codex 获得完全一致的基础上下文。
- 常驻入口只承载跨任务不变量，降低无关信息对普通任务的干扰。
- 详细知识仍可按路由获取，没有用“瘦身”换取规则缺失。

### 2. 建立 OpenSpec 有界检索

**完成内容**

- 当任务需要确定、解释、修改或验证项目行为、领域规则或正式契约时，Agent 必须先按任务语义和受影响路径检索 `openspec/specs/`。
- 检索只读取命中的正式规范；未命中时不扩展为全量读取。
- 同一任务复用已读取规范，只有范围变化时才重新检索。
- 仅当任务实际属于某个 active Change 或 Program 时，才加载对应在途工件。

**优化成果**

- 行为变更、缺陷诊断、代码审查和验收等关键场景能够主动找到权威规范。
- 普通编辑、机械 Git 操作等无关场景不会被 OpenSpec 全量加载反向拖累。
- 兼顾了规范读取的覆盖率与上下文成本。

### 3. 收敛 Agent 执行治理

**完成内容**

- 只建立真实依赖所需的阶段，以最小充分测试、审查和验收证明结果。
- 将必要测试、代码审查、验收和阻断修复放在最后一次实质修改之后完成。
- Git 提交只消费仍有效的收口结论，不重新发起广泛审查或回归。
- 将目标、阶段交接和上下文压缩分开治理，不使用固定阈值制造额外动作。
- 明确范围控制和 `S/M/L/XL` 定性成本预警，阻止可选重构与扫描自然膨胀。

**优化成果**

- 执行链从机械分阶段转为由风险和依赖驱动。
- 减少重复测试、重复审查和重复上下文装载。
- 在缩短任务链的同时保留领域硬门禁和高风险验证。

### 4. 明确 SubAgent 使用边界

**完成内容**

- SubAgent 只用于边界清晰，且独立复核、真实并行、专门知识或上下文隔离收益高于协调成本的任务。
- 共享 Runtime、资源身份、破坏性资源操作、生成契约和发布切换等受保护范围，必须由未参与实施的 verifier 独立复核。
- 可重复、局部且可判定的 Git 操作不再委派 SubAgent，改由确定性程序执行。

**优化成果**

- 避免为普通任务引入额外编排、等待和上下文同步成本。
- 在真正需要独立性的位置保留可判定的复核结论。
- SubAgent 从默认拆分手段变为有明确收益条件的执行能力。

### 5. 建立确定性 Git 提交与结果报告

**完成内容**

- 通过 [git-commit Skill](https://github.com/LuckyZen/WorldTourCasino/blob/classic_vegas_web_refactor/.claude/skills/git-commit/SKILL.md) 将普通提交与推送收敛为 `prepare` 和 `deliver` 两个批次。
- `prepare` 一次完成范围预检、远端同步和状态绑定；`deliver` 一次完成精确暂存、提交、推送和同步验证。
- 辅助程序校验仓库、分支、HEAD、upstream 和暂存范围；失败立即停止，普通快速路径不执行 force push。
- 成功结果只保留提交标题、弱化的交付元信息、提交说明、文件统计、总计和未提交边界。
- 删除原始 `fullLog`、重复身份字段和低价值远端信息，避免模型再次整理同一份 Git 输出。

**优化成果**

- 主 Agent 的普通 Git 编排由四段收敛为两段，远端交互稳定为一次 fetch 和一次 push。
- 提交范围和前置状态由程序绑定，减少状态漂移与误提交风险。
- 用户可直接查看提交内容和未提交边界，不需要阅读原始日志或复制中间结果。
- 八个连续的 Git 流程迭代提交已合并为最终提交 [70f5efa](https://github.com/LuckyZen/WorldTourCasino/commit/70f5efa2b053facfd7080ee48568070f1c150876)，交付历史保持聚焦。

### 6. 分离系统级记忆与项目规则

**完成内容**

- Nowledge 采用“一次逻辑任务一次有界检索、相邻回合复用”的系统级路由。
- 只有任务范围变化、需要新的跨工具事实或精确历史时才重新检索。
- 机械提交和推送不单独触发记忆检索。
- 该规则不写入 `AGENTS.md`，避免把宿主能力固化成项目行为。

**优化成果**

- 减少同一任务中的重复 Memory 路由和调用。
- 项目基础上下文保持工具无关，系统能力可以独立演进。
- 跨会话结论仍能被检索和复用，不依赖不断扩张的仓库规则。

1. 项目行为以 OpenSpec 为权威，基础上下文以 `AGENTS.md` 为唯一来源。
2. Claude Code 与 Codex 共享入口、共享 Skill 和相同硬门禁。
3. 详细规则、领域规范和长期 Program 均按需加载。
4. 实质工作先收口，Git Skill 再执行确定性交付。
5. SubAgent、Nowledge 和上下文压缩各自解决独立问题，不再混入常驻项目规则。
6. 治理实现由提交 `15d8e24`、`c6db266` 和 `70f5efa` 承载；本次文档收口时没有未归档的 active Change。

本文是治理结果摘要，不替代实际规则与规范。发生冲突时，以 OpenSpec、`AGENTS.md`、命中的 Skill 和专项规则为准。
