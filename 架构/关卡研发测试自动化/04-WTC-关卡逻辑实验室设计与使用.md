## 一、设计

设计视角：工具如何工作——服务形态、总体架构、静态提取与图结构、规格包契约、覆盖计量与插桩、运行上下文与轨迹、可靠采集、协议注入、看板报告与验收。

### 0. 当前服务形态

- 默认入口为 `scripts/lab-server.js`：在拥有源码的设备中，一个本地进程承载按需提取任务、当前发布注册表、统一看板、覆盖采集及录制游戏资源。测试设备只打开带探针的游戏页面，不部署提取器，也不手动传输规格包。原有单包服务和 CLI 继续作为独立调试入口。
- `src/lab-registry.js` 只管理人工指定并成功发布的模板/风格组合。后台 `lab-worker.js` 依次提取、校验、构建；规格、匹配的 bundle 和服务地址核对成功后，原子替换 `registry.json` 中当前指针。失败保持已发布内容，新指纹清零覆盖，相同指纹保留采集数据。新服务只清理自己管理的旧包，保存有界的节点变更摘要，不扫描关卡、不做批量或历史版本列表。
- 提取任务在工具栏显示当前关卡最新状态的固定尺寸摘要，历史任务放入独立侧边抽屉。抽屉消费 `/lab` 返回的近期任务，失败堆栈默认折叠，轮询保留已展开详情、焦点和内部滚动位置。摘要只受当前关卡最新任务影响；任务数量、错误长度及抽屉开关不改变主页面布局。“提取任务”与“规格变更记录”是独立入口。
- 每关数据接口位于 `/levels/<风格-ID>/`，游戏固定使用 `/play/` 与同一个服务端口，关卡和指纹通过 `?level=<风格-ID>&packageId=<指纹>` 携带。`/publication` 允许所有关联旧客户端读取当前发布身份及游戏 URL，独立于单客户端控制命令。首次握手匹配后才能录制，新发布触发受影响页面中断旧会话、有限收尾和自动重载；构建身份再次不匹配时阻断录制，避免无限重载。旧批次始终携带原身份，不能改标签混入当前计数。
- 跨设备部署需明确监听地址和 public URL。端点变化参与托管包身份，已有旧端点构建提示重新更新。跨版本兼容命中继承尚未实现，人工标注仍参与包指纹，亦会触发新发布与覆盖重置。以下原始规格/计量约定继续适用，其中 `out/v02/history` 和两个独立服务器属于保留的 CLI 调试模式。
| 接口 | 行为 |
| --- | --- |
| `GET /lab` | 当前可选关卡及最近 50 条任务，新任务在前 |
| `POST /lab/analyze` | 接收 `{levelId, flavor}`，返回 202 与任务；已有任务运行时返回 409 |
| `GET /levels/<key>/publication` | 所有页面每秒握手，返回当前 `packageId`、`revision`、`buildUrl`、`ready` |
| `GET /levels/<key>/changes` | 节点增删改、位置迁移和无法配对摘要，不提供历史覆盖 |
| `/levels/<key>/{spec,coverage,events,source,export,recording,control,control/ack,trace}` | 复用原单包接口；控制必须指定当前版本且在线的 `clientId` |
| `GET /play/?level=<key>` | 可收藏的固定入口，自动跳转到当前指纹参数 |
| `GET /play/?level=<key>&packageId=<指纹>` | 当前录制游戏；过期参数跳转当前参数，路径与端口不变 |
| `GET /play/game.min.js?level=<key>&packageId=<指纹>` | 当前加载器 bundle，参数缺失或过期时拒绝请求 |
| `GET /play/res_oldvegas/game.js?level=<key>&packageId=<指纹>` | 当前录制 bundle，严格匹配关卡与指纹 |

- 发布顺序为：生成候选规格、校验、构建、再次核对源码与工具输入、核对两个 bundle、原子写当前指针、清理旧受管目录。游戏页面在发布切换前继续使用旧包；失败不会切换当前指针。页面发现新版时停止旧会话，最多收尾一秒，再更新固定地址的指纹参数并重载。新页面握手后仅恢复用例与名称，建立新会话；不会恢复注入或 Spin。同一标签页的同一端点与目标版本只自动跳转一次，保护记录保存在 `sessionStorage`，存储不可用时阻断自动跳转。
- `game-document.js` 复用主工程 HTML，并在 Cocos 启动前加入 `managed-entry.js`，把主游戏 bundle 的动态加载地址绑定到当前页面的关卡与指纹参数。普通引擎、美术资源共用固定路径；两个录制 bundle 必须显式携带参数，不依赖 Cookie 或 Referer，避免多页面互相覆盖归属。旧 `/play/<key>/<指纹>/` 页面地址兼容跳转到参数入口；已打开旧页面的资源在其包仍是当前版本时可加载，过期资源仍返回 409。
- 旧版尾部数据在新版发布后会被拒绝，其未确认数量保存为重载诊断；看板区分致命阻断与非致命截断警告。覆盖快照始终独立于轨迹日志。服务只保存每关当前包与采集数据，每次更新的节点明细最多各 200 项，歧义组每侧最多 20 项，并标记截断；变更记录按次追加。提取和更新由人工发起，没有文件监视或全关扫描。
### 1. 目标与适用范围

- 工具回答三个问题：指定关卡包含哪些可定位到源码的结构与决策；某次测试实际执行了什么；约定源码范围内还有哪些标准覆盖项未命中。
- 首版使用现有 CV 浏览器开发构建，支持人工测试与自动化测试共用采集链路。托管入口仅接受 CV（`oldvegas`）；独立解析器也接受 DH 风格，但 DH 的游戏加载配置尚未完成托管适配。引擎、平台、通用系统和服务端判奖保留为边界。工具不提供确定性回放、自动场景求解、真机采集、CI 覆盖率门禁或全部路径证明。
- “完整”指选定源码全部解析、函数与分支具备归属和位置、无法确定的关系逐项披露。它不等于玩法意图已经验证，也不等于公共代码依赖可被动态 JavaScript 静态穷举。

#### 2.1 核心技术原理

- 提取器采用基于 AST（Abstract Syntax Tree，抽象语法树）的静态程序分析，叠加本项目框架规则，生成可定位源码的规格图谱。静态提取无需执行游戏，也无需逐关调用 AI；运行录制再补充实际命中与执行顺序。
> [全屏打开 ↗](/WTC-Docs/diagrams/09-static-analysis.archify.html){target="_blank"}

<iframe src="/WTC-Docs/diagrams/09-static-analysis.archify.html" style="width:100%;height:82vh;border:1px solid var(--vp-c-divider);border-radius:8px;" title="2.1 核心技术原理"></iframe>

- AST 表达源码的嵌套结构，例如某个 `if` 属于哪个函数、条件表达式及两个分支分别是什么。规格图在这些结构上增加跨文件引用、继承、装配、调用、状态读写和控制流连接，可以包含循环关系。看板展示的是经过整理的关系图，而非直接展开原始语法树。
#### 2.2 Acorn 与相关组件

- [Acorn](https://github.com/acornjs/acorn) 是 JavaScript 语法解析器，负责把源码解析为 ESTree 风格的 AST；`acorn-walk` 提供遍历节点的能力。解析得到 `FunctionExpression`、`IfStatement`、`CallExpression` 等节点类型，以及起止字符偏移、行列位置。Acorn 不执行源码，也不解释 Slots 玩法意图。
- parse.js 使用 Acorn 解析源码和收集注释，再由本项目规则整理为中间表示（IR）：保留 AST 与源码，并索引类、函数、变量绑定、`require`、导出符号和未解析项。例如，Acorn 将 `Base.extend({...})` 识别为调用表达式，本项目规则进一步把它识别为类及其方法；组件、Action 和 Process 的含义同样来自框架适配。
| 技术组件 | 在本工具中的职责 | 实现入口 |
| --- | --- | --- |
| Acorn / acorn-walk | 静态语法解析与遍历；录制构建末尾另用 Acorn 校验 ES5 输出 | parse.js、instrument.js |
| 项目分析规则 | 解析入口与依赖、识别框架结构、构造图和披露缺口 | resolve-level.js、extract.js、graph.js |
| Istanbul | 生成标准覆盖映射和计数插桩，汇总语句、函数、分支与行覆盖 | coverage.js、instrument.js，详见 5.1 |
| Babel | 在录制构建中解析和变换 AST，配合 Istanbul 加入计数，再降级词法声明、加入轨迹探针并生成源码映射 | instrument.js |
| Cytoscape.js / ELK | 图交互与分层布局，消费已有规格和覆盖数据 | web/app.js |

- 静态结构提取与录制插桩使用各自的解析链路。Acorn AST 用于本项目静态规则；Istanbul/Babel 从相同源码生成覆盖映射与插桩代码，并不直接消费 Acorn AST。两条链路通过文件身份、原始源码位置和覆盖坐标关联，规格包指纹用于防止不同输入版本的数据混合。
### 3. 静态范围与图结构

#### 3.1 关卡身份

- 模板入口沿 `subject_tmpl_<ID>.json` 的 `client.slotSceneType`、`SlotSceneType` 枚举和 `SlotSceneFactory` 注册关系解析 Scene。数字前缀模块目录纳入目录内全部 JavaScript；单文件 Scene 纳入该文件内全部类与函数。文件、目录高级入口必须能识别 MachineScene，并检查显式模板与工厂解析结果一致。
- 风格覆盖文件按原工程规则替换基础源码。身份保存 `levelId`、`flavor`、`sceneType`、`sceneFile`；运行事件用 `roomId` 字段保存实际 `subjectId`，防止共用 Scene 的不同模板或房间混淆。高级入口建议始终显式提供 `--level-id`，避免多个模板共用 Scene 时的推定歧义。
#### 3.2 公共依赖边界

- 解析器通过作用域绑定、相对 `require`、导出符号、继承、构造、装配属性、调用和 Action 注册追踪引用。默认公共范围保守纳入 `src/newdesign_slot` 下 Scene、组件、Controller、Process、Action 等业务目录，以及适配的 `SlotFlow`。
- 当前纳入单位是文件：符号引用确定候选文件后，该文件内全部函数与分支保留在分母中。条件装配、覆写候选和未加载方法不会因运行未命中被删除。仅导出列表或注册表声明本身不会把全部注册项加入范围。
- 引擎调用、全局服务、通用辅助模块及 `--own-only` 排除的公共调用显示为边界。动态构造、未知基类、动态注册键、mixin 和无法静态确认的调用保留源码位置与原因。扩展公共范围需要修改明确的策略或适配器，并重新生成规格包。
#### 3.3 结构与解释

- 本项目在 Acorn AST 上识别 `.extend`、匿名类、prototype 方法、普通函数和回调。图包含文件、类、方法、标准分支、语义决策、状态和边界节点，以及包含、继承、装配、调用和结构控制流关系。函数具有仓库相对路径与起止源码位置。
- 函数内部按语句顺序连接条件、循环、switch、返回和异常边，形成简化控制流图（CFG，Control Flow Graph）。表达式内部的三元与短路决策只附加到所属语句，没有构建完整表达式 CFG；带标签跳转、经过 `finally` 的非正常退出等保留解析缺口。
- 调用关系结合导出引用、继承查找和框架规则确定，包括 `this._super`、`Action/Process.context`、SlotFlow 和 Process 数组等。状态读写来自成员访问及赋值的语法路径；当前没有实现完整变量值传播、对象别名分析、符号执行或路径可达性证明。因此结构枚举可核查，候选调用关系与路径是否真的发生仍需运行证据。
- 进房、Spin、FreeSpin、Bonus、结算等分组依据方法命名和可识别的源码入口归纳，属于规则分类。分组与静态边不保证真实执行先后，实际运行以事件序号、调用和异步关联为证据。人工中文说明必须带 `author` 与 `source`，显示在节点详情和 Markdown 中；它不会消除未解析项或替换条件原文。
#### 3.4 通用机制与代码演进

- 所有关卡共用入口解析、AST 遍历、框架规则和规格生成程序。规则围绕 Scene、组件、Controller、Process、Action 等框架结构维护；关卡 ID、风格、配置和源码作为输入。沿用已适配结构的新关由人工指定后直接提取，不需要逐关编写分析脚本或让 AI 重新理解整关。
- 源码或配置发生普通变更时，人工更新该关即可重新分析当前范围，并按第 4 节生成包身份。托管服务只有在匹配的录制构建成功后才发布，随后通知游戏重载；相同指纹保留覆盖，不同指纹清零并保存变更摘要，默认看板只统计当前版本。当前没有自动文件监视或全关扫描。
- 维护成本主要来自公共框架规则、依赖边界和语法支持。即使框架基础结构不变，规则无法确认的具体动态表达式仍会进入缺口清单；需要提高其解析精度时，应补充共享规则及针对性验证，再重新提取受影响关卡。普通重新提取使用同一套程序，不产生逐关 AI 分析依赖。
### 4. 规格包契约与版本

- 结构契约为 spec-package-v02.schema.json，`specVersion` 为 `0.2.0`。`config`、`assembly`、`state-contract`、`server-contract` 等旧槽位保留，并通过 manifest 标明 `present`、`empty` 或 `absent`。
| 路径 | 核心内容 |
| --- | --- |
| `static/manifest.json` | 版本、指纹、profile、源码指纹、完整性与工具输入 |
| `static/graph.json` | 节点、边、源码坐标及人工标注 |
| `static/coverage.json` | 全部文件的 Istanbul 映射、`own/shared` 分类和零计数 |
| `static/scope.json`、`unresolved.json` | 纳入理由、边界及逐项分析缺口 |
| `static/branches.json` | 独立语义决策和分支臂定义 |
| `sources/`、`slices/` | 完整源码快照与兼容的类方法切片 |
| `targets.json` | 构建目标、源码指纹及范围 |
| `recording/` | 独立 loader、bundle、构建信息 |
| `traces/batches/` | 已确认批次的持久化日志 |

- `packageId` 对规范化输入计算 SHA-1，包含 profile、所选源码、解析时读取的相关源码、模板与工厂等解析输入、工具源码及依赖清单、`ownOnly` 和规范化人工标注。文件内容参与身份，本机绝对目录和人工标注文件的存放路径不参与身份。节点 ID 用仓库相对路径及源码坐标定位，内容漂移由包和文件指纹识别。
- 相同指纹重分析保留录制数据；不同指纹先将整个旧包移动到同级 `history/<包目录名>-<旧指纹>`，名称冲突时加编号。非空但无 manifest 的目录拒绝覆盖。采集与合并只接受相同 `packageId`。旧 0.1 包支持只读查看，旧 JSONL 不换算成新口径百分比。
### 5. 覆盖计量与插桩

#### 5.1 标准口径

- [Istanbul](https://istanbul.js.org/) 是 JavaScript 代码覆盖率工具体系。其核心方式是源码插桩：先建立可计数位置的映射，再在相应位置加入计数操作；游戏运行时累积命中次数，最后根据映射汇总覆盖比例。本工具直接使用 `istanbul-lib-instrument` 和 `istanbul-lib-coverage`，人工测试与自动化测试都消费同一套计数机制。
| 数据 | 含义与用途 |
| --- | --- |
| `statementMap` / `s` | 语句 ID 到源码位置的映射 / 对应执行次数 |
| `fnMap` / `f` | 函数 ID 到源码位置的映射 / 对应调用次数 |
| `branchMap` / `b` | 分支 ID、类型及各臂位置的映射 / 每个分支臂的命中数组 |
| 行覆盖 | 由语句位置和计数按 Istanbul 规则汇总，没有单独的行探针 |

- 提取阶段，coverage.js 用 `createInstrumenter` 为选定范围生成覆盖映射，形成固定分母。录制构建阶段，instrument.js 用 Istanbul 的 `programVisitor` 在 Babel AST 上插入标准计数，并通过覆盖访问器将命中归入原关卡、会话和用例上下文；Istanbul 本身不负责业务归属。
- 覆盖映射与 source map 用途不同：前者将计数 ID 对应到原始源码位置，后者将插桩后生成代码的位置对应回原始源码。它们共同支持看板定位和构建调试，不能互相替代。
- 标准语句、函数、分支和行覆盖均由 Istanbul 映射定义；分支率为命中臂数除以总臂数。例如两个 `if` 各有两臂，共命中三臂时为 `3/4 = 75%`，不能按“两个分支点均到达”报告为 100%。行覆盖由标准语句位置及命中按 Istanbul 规则汇总。
- 每次报告先从规格包创建全部零计数文件，再合并所选用例。未加载文件也保留零命中；自有与公共源码分别报告。短路决策、switch 首次选择与穿透、无匹配、循环、break/continue、catch/finally 等属于补充语义计数，不改变标准分支分母。
- 标准分支率不代表全部路径、条件组合或 MC/DC。补充决策也只反映已定义的语义臂，不能据此证明所有异常来源或全部循环路径。
- 标准计数回答哪些位置执行过、执行了多少次；执行先后、异步因果和关键状态可由本项目轨迹探针记录。图节点通过 `coverageRef` 关联标准覆盖位置，语义决策与轨迹通过各自的节点 ID 和源码位置关联。看板将这些数据叠加展示，标准百分比由 Istanbul 汇总，独立于图节点的展示数量和布局。
#### 5.2 插桩顺序与行为保持

- 插帧
1. 静态分析用原始风格源码生成 Istanbul 覆盖映射。
1. 录制构建校验目标、风格、源码、解析依赖和工具输入未漂移。
1. Browserify transform 消费构建流源码，生成标准计数，再用 Babel 官方块作用域转换处理 `let`、`const`（启用 TDZ 检查），随后加入函数、控制流和状态探针，组合 source map。
1. 后加轨迹探针不进入标准分母；覆盖计数访问器每次根据当前上下文选桶，避免缓存另一用例的计数对象。
1. Acorn 以 ES5 校验输出；失败终止录制构建。运行时和控制轮询自动随测试 bundle 加载。
- 探针保留表达式返回值、短路求值、原异常传播和副作用次数；函数退出通过 `finally` 记录。成员赋值在完成后记录结果摘要，避免为了快照额外读取 getter。对象仅保留类型摘要，字符串有限长；`++`、`--`、`delete` 不单独录值。
- 块作用域转换发生在轨迹函数包裹之前，保留局部遮蔽、循环闭包、声明前访问异常与常量写入限制。转换生成的辅助代码不计入标准覆盖分母，映射与源码快照仍指向输入源码。此步骤只处理词法声明，其余不支持的非 ES5 语法仍明确终止构建。
### 6. 运行上下文与轨迹

- 会话由 `start` 创建，用例由 `scene` 标记，Spin 在已适配的请求入口关联。活动会话内再次 `start` 不创建新会话。关卡上下文从匹配模板的 Scene 生命周期和对象关系建立，并保留实际房间身份；无法证明归属的执行进入 unknown 桶。
- 计数桶身份包含录制器、会话、用例与已知/未知归属。公共函数仅在已知目标上下文中提高关卡覆盖；仅凭当前页面或最近进过某关不能归属。停止录制结束活动会话，但已绑定的迟到回调仍携带原会话与用例身份。默认保留 5 秒、最多 2,000 个回调和 20,000 次计数的短尾窗口；窗口结束后旧上下文静默失效，不能再次把看板状态改回收尾中。命中回调或计数上限时以 `tailCutoffs` 标记采集不完整。
- 已适配链路包括浏览器定时器与动画帧、Cocos schedule/事件、SlotFlow、Action、常用 slotUtil 动画回调和协议请求回调。排队时复制上下文，执行时恢复，退出时还原调用栈；取消定时和移除监听保留原函数到包装函数的关联。尚未适配的异步机制不保证自动传播。

<iframe src="/WTC-Docs/diagrams/10-record-collect.archify.html" style="width:100%;height:82vh;border:1px solid var(--vp-c-divider);border-radius:8px;" title="6. 运行上下文与轨迹"></iframe>

- 默认为实时摘要模式：浏览器每 500ms 将发生变化的 Istanbul 计数、补充决策和用例/注入状态发送给服务，看板可实时查看覆盖率和图节点状态。摘要批次不携带函数、网络、异步和状态写入的完整过程，服务仅在内存合并它们，因此时间线为空且不会形成持续增长的批次文件。停止时发送完整累计快照作为可恢复记录；页面在停止前意外关闭或服务重启时，尚未最终落盘的当前会话摘要无法恢复。
- 需要排查执行顺序、异步因果或协议时，在开始录制前显式设置 `window.__wtcAnalysisConfig.traceDetail = true`。详尽模式才保留事件，事件含 `sessionId`、`caseId`、`seq`、时间及可用的 `spinId`、`callId`、异步任务、方法/决策坐标和房间信息；时间线按事件时间与序号排列，因果关系通过关联字段检查，它不是跨浏览器分布式因果排序器。
### 7. 可靠采集与恢复

- 覆盖快照与顺序事件独立存储。默认模式周期性发送增量摘要但不落盘；停止后写入完整累计快照。详尽模式下，事件队列和本地历史各默认最多 100,000 条，每 500ms 发送至多 10,000 条，ACK 超时默认 10 秒。快照只发送 `s/f/b` 等计数，固定映射由规格包提供。ACK 后继续排空积压，失败保留同一批次重试。
- 覆盖快照采用确认式增量：首次或发生变化的文件和语义计数才进入批次，服务端按累计最大值合并；同一批次未确认时保留原快照并原样重试，确认后才清除其待发标记。这样不会把整关的覆盖计数重复写入每个事件批次。
- 看板可清空当前规格包的录制数据，但只在所有运行端空闲且没有待确认启停指令时允许执行。服务删除该包的批次文件并重置内存汇总、会话和事件索引，同时保留一个极小的已清空会话标记和重置标识，防止服务重启后迟到的旧批次重新写入。运行端在发布轮询发现重置标识变化后会丢弃已结束会话与其陈旧批次，并为当前会话重新标记摘要；新会话可正常开始。规格包、源码、图谱和关卡变更记录不属于录制数据，不受此操作影响。
- 采集服务校验版本、坐标、非负整数计数和分支臂形状，先写临时文件并 `fsync`、重命名，再确认。重复 `batchId` 且内容一致只返回确认；同 ID 内容不同则拒绝。事件按录制器、会话、序号去重。服务启动重放完整批次 JSON，损坏数据显式计入恢复异常。
- 同一录制器/会话/用例的累计快照逐计数取最大值，故旧快照迟到或重试不会再次累计；不同桶在查询时相加。例如同桶依次收到 5、3、5、8 次命中，最终为 8；另一用例命中 2 次，汇总为 10。unknown 桶保留但排除于目标报告。
| 状态 | 解读 |
| --- | --- |
| `droppedEvents` | 待发送顺序事件溢出，后续计数快照不能补回缺失顺序 |
| `droppedHistoryEvents` | 浏览器本地历史滚动淘汰，不代表服务端已确认日志丢失 |
| `pendingEvents`、`pendingBatchId`、`sending` | 浏览器尾部是否排空，停止后仍需检查 |
| `invalidBatches`、恢复错误、最近摘要拒绝原因 | 启动恢复时存在无法接受的历史批次；实时拒绝记录批次元信息和 HTTP 原因，并通过看板与浏览器 `transportErrors` 反映 |
| `unknownBuckets` | 存在无法证明关卡归属的计数桶 |
| `complete` | 服务端当前所知状态的汇总，不能证明断线浏览器没有尚未上报的数据 |

- 控制命令通过轮询领取和 ACK，接收成功仅表示排队。`/recording` 独立返回运行端状态、指令及恢复进度；看板每秒查询，不等待覆盖和轨迹报告。界面区分待录制、正在启动、录制中、正在停止、正在保存尾部及离线。相同页面待确认的重复启停合并；已经处于目标状态时不重复执行；等待尾部保存时不能开始新会话。
- 停止会保留已绑定迟到回调的原会话、用例和房间归属，但尾部最多持续 5 秒、2,000 个回调和 20,000 条记录。超过任一上限时切断旧会话归属并上报 `tailCutoffs`，看板将该会话标为采集不完整；该上限防止周期性定时器或动画回调无限延长停止状态。
- 运行端通过既有发布与控制轮询上报轻量状态和单调递增 revision，ACK 固定原状态快照，迟到 ACK 不覆盖更新心跳。现有旧构建由成功 ACK 与最高事件序号的会话生命周期推导状态；停止 ACK 只确认执行，接收停止事件后才确认已保存尾部。普通迟到回调不改变会话状态。采集质量、未归属计数和静态分析缺口与录制状态分别显示。
- 托管模式只允许指定的当前版本在线 `clientId` 领取，其他页面继续独立录制；独立旧服务仍采用多个浏览器中的单领取模式。服务 epoch 防止重启后的旧游标跳过新命令，旧 epoch 和旧规格 ACK 均拒绝。待执行命令 30 秒未确认则标为失败。批次日志可恢复，内存中的控制命令不随重启恢复，应按运行端状态确认结果。
- 浏览器离线导出保存当前本地历史、累计快照及未确认批次，无法恢复已滚动淘汰的历史。服务端保留原始批次日志，逐批异步恢复覆盖与索引；恢复期间轻量状态和控制继续响应，报告及新批次等待恢复完成。最近事件缓存最多 10,000 条且序列化体积不超过 16 MiB，批次接受位图及录制器/会话序号区间负责精确去重。索引仍随批次和不连续序号增长，磁盘日志不自动清理。
### 8. 协议记录与人工注入

- 网络适配同时观察普通请求回调与 push，避免只记录推送而遗漏普通响应。支持的业务协议为进房、slot_param、Spin 及压缩 Spin 变体。协议轨迹使用摘要并保留可用于所支持响应复测的数据，具体字段由适配器决定。
- 人工注入必须提供带协议类型的完整服务端响应，只替换下一次符合协议、请求类型、会话、用例和可选房间条件的请求响应。响应处理函数仍只执行一次，注入本身不产生请求；push 是录制入口，不是注入替换入口。同一时刻只有一个待命注入，停止时清除，消费后才把对应用例标为 injected。
- 人工响应必须有来源并匹配当前账号状态。292 红色 FreeSpin 与重触发样例验证了客户端流程和一次性消费，但回用余额字段产生一致性开发警告，不能作为账户同步、服务端判奖或无弹窗视觉验收。
### 9. 看板与报告一致性

- 看板使用 Cytoscape.js 展示图谱，ELK 负责分层布局；支持分层展开、源码定位、标准分支臂命中、关联用例、未覆盖清单和执行事件。覆盖状态为未覆盖、部分覆盖、已覆盖及未知。外部边界和缺乏计量证据的节点不能涂成已覆盖。
- 实时 `/coverage` 与 CLI/HTTP 报告共用 `TraceStore.report`。覆盖可按会话和用例筛选，Spin 筛选只作用于轨迹。当前 `newHits` 指最近接收批次使全局首次命中的标准分支臂，再按当前选择过滤；它不是完整“本次会话相对历史基线”的差集，批次重放后也不能作稳定的历史增量。
- 图谱每页最多 250 节点。详尽模式下时间线每页 500 事件，后端常规 `/events` 默认最新 1,000 条、最多 10,000 条，返回完整匹配总数和 `nextCursor`；`before=<nextCursor>` 读取更早事件，查询只维护有界结果集，不排序全部事件。`all=1` 及离线导出超过 100,000 条事件或事件序列化体积 32 MiB 时明确拒绝（HTTP 413），提示缩小会话、用例或 Spin 范围；不静默截断导出，原始日志仍保留。
- 离线 HTML 内嵌图谱依赖、源码和所选全部事件，无 CDN 或采集服务依赖；覆盖选择固定为导出范围，Spin 仍可筛轨迹。大型报告可达数十 MB，本轮实际打开验证约 90MB。Markdown 适合规格评阅，Mermaid 适合结构图交换，JSON 保留机器可读汇总。
### 10. 验收与维护

- 验证分为静态规格、插桩语义、采集与归属、浏览器源码夹具、看板及完整游戏六层。自动化检查覆盖固定分母、短路与 switch 求值、副作用、异常、递归、异步取消、迟到回调、批次去重、重启恢复和跨版本拒绝。Golden 仅约束代表性事实，不作为全部源码分母。
- 292、287、170 已完成 CV 完整游戏进房、普通 Spin、退出重进，结果包括帧间隔、堆内存和日志状态。292 另有人工 FreeSpin/重触发证据。录制结果中较低的覆盖率是该测试范围的真实缺口，不是工具验收失败；帧与内存数据含资源加载、未强制 GC，不能直接解释为纯探针开销或真机性能。
- 扩展语法、公共范围、协议或异步机制时，先补可人工核算的针对性夹具，再验证原始/插桩行为一致及错误归属隔离。修改纳入指纹的工具或源码后重新分析、构建；托管服务保留变更摘要，仅独立 CLI 保留旧包历史。新增后续能力应显式区分已实现与计划，尤其是会话基线增量、流式大报告导出和更广的异步适配。

## 二、安装与使用

操作视角：环境准备、本地统一服务、分析关卡与命令、录制与补测、报告与接口、规格包目录、测试与验收。命令的工作目录除注明外均为 tools/analyzer。

### 2.1 环境

- Node.js 18 或以上；分析工具使用现代 JavaScript，注入游戏的运行时代码必须为 ES5。
- 主工程已安装现有构建依赖，包括 Browserify；分析器依赖单独安装。
- 完整游戏联调需要已有 CV 本地资源、配置、账号和可连接的游戏服务。录制服务器不会提供游戏业务服务。
- 浏览器验收使用 Playwright，默认启动本机 Chrome。看板测试在没有 Chrome 时会尝试 Playwright 自带 Chromium。
以下命令除特别注明外，工作目录均为 `tools/analyzer`：

```bash
cd tools/analyzer
npm install
```

### 2.2 本地统一服务（默认）

- 在拥有源码和现有游戏资源的设备启动一个服务：
```bash
npm run serve -- --port 3320
```

- 打开 <http://localhost:3320>，指定模板 ID 执行提取。首版托管入口仅接受 CV（`oldvegas`）。服务完成分析、校验和录制构建后，该关才进入关卡选择列表。看板可切换已提取关卡、更新当前关、打开匹配的录制游戏；不扫描全关、不批量处理，也不需要手动传输或导入规格包。
- 游戏使用同一端口下的固定 `/play/` 入口：`http://localhost:3320/play/?level=oldvegas-292` 可长期收藏，打开时服务自动补充当前 `packageId` 参数。指纹不再放入路径，新版发布只更新查询参数。
- 服务默认将当前产物和采集数据写入 `out/lab`。同指纹更新保留覆盖，新指纹更新保守重置该关覆盖，只保留精简节点变更记录。新规格和游戏构建共同发布，失败保持原版；所有关联测试页面通过轮询感知新发布，有限收尾后自动重载。首次握手匹配前不允许录制，刷新后仍不匹配会停止并提示错误，不无限刷新。旧页面迟到数据不会进入新统计。
- 看板的“清空当前关卡录制数据”只作用于当前 `packageId`：删除覆盖、会话、用例、轨迹和持久化录制批次，规格包及关卡变更记录保持不变。录制、尾部保存或启停指令待确认时服务会拒绝清空，必须先完成停止。
- 测试设备位于另一台机器时，使用服务设备可达的局域网地址：
```bash
npm run serve -- --host 0.0.0.0 --port 3320 --public-url http://192.168.1.20:3320
```

- 将示例 IP 替换为实际服务设备地址；两台设备打开同一服务提供的看板或游戏地址。游戏测试端只加载录制构建并上报，不运行提取器。已发布后改变 `--public-url`，需更新所使用关卡以重新绑定采集地址。额外托管游戏来源可用 `--allow-origin https://测试页面来源` 指定。端口占用时改用空闲端口，并保持 public URL 一致。
### 2.3 分析关卡

- 默认风格为 CV，等价于 `--flavor oldvegas`。模板 ID 会沿风格配置、Scene 类型和工厂解析入口。
```bash
node scripts/analyze.js 292 --flavor CV --out out/v02/spec_292
node scripts/analyze.js 287 --flavor CV --out out/v02/spec_287
node scripts/analyze.js 170 --flavor CV --out out/v02/spec_170
```

- 也支持文件、目录入口。使用单文件时显式提供模板 ID，以绑定运行时房间与模板身份。
```bash
node scripts/analyze.js ../../src/newdesign_slot/scene/292_rose_romance \
  --level-id 292 --flavor CV --out out/v02/spec_292

node scripts/analyze.js ../../src/newdesign_slot/scene/DashingWinMachineScene.js \
  --level-id 170 --flavor CV --name "Dashing Win" --out out/v02/spec_170
```

| 参数 | 含义 |
| --- | --- |
| `--flavor CV` / `oldvegas` | CV 构建配置，也是默认值 |
| `--flavor DH` / `doublehit` | DH 构建配置；必须与后续录制构建一致 |
| `--out <目录>` | 默认 `out/v02/spec_<模板 ID>` |
| `--level-id <ID>` / `--name <名称>` | 文件或目录高级入口的身份与名称 |
| `--own-only` | 只分析关卡自有源码，公共调用保留为边界；会改变分母与规格指纹 |
| `--annotations <JSON 文件>` | 导入有作者、来源的人工说明 |
| `--no-validate` | 仅跳过生成后的规格校验，排错使用 |

- 分析会解析 `.extend`、匿名类、prototype、普通函数与回调，建立文件、类、方法、分支、状态、流程和边界关系。公共范围由可解析的引用、导出符号、继承和装配关系决定；被纳入的文件保守枚举全部函数与分支。
- 动态调用、无法确定的装配和非关卡系统通过边界或分析缺口登记。`manifest.completeness` 和 `static/unresolved.json` 是完整性证据；没有运行到某段代码，不会将它从静态分母移除。
#### 2.3.1人工中文说明

- 说明是有来源的人工标注，不会替换源码条件、改变代码分类或消除未解析项。输入格式：
```json
{
  "annotations": [
    {
      "nodeId": "src/newdesign_slot/scene/292_rose_romance/RoseRomanceMachineScene292.js#fn:L140C23",
      "text": "此处说明由维护者根据玩法验收记录填写。",
      "author": "测试团队",
      "source": "玩法验收记录的文档链接或记录编号"
    }
  ]
}
```

- `nodeId` 必须使用当前 `static/graph.json` 中实际存在的 ID，示例坐标仅展示格式。也可将 `nodeId` 替换为 `file`（仓库相对路径）和 `line`（起始行号）。该行必须唯一匹配一个节点，否则分析会列出候选 ID 并失败；`text`、`author`、`source` 均为必填字符串。
```bash
node scripts/analyze.js 292 --flavor CV --annotations notes-292.json \
  --out out/v02/spec_292
```

- 规范化说明保存在 `graph.annotations` 与对应节点的 `annotations` 中，看板详情和 Markdown 报告均显示作者、来源。说明内容参与 `packageId`；搬动输入 JSON 的本机路径不会改变规格身份。
#### 2.3.2 重分析与历史

在 `out/v02/spec_292` 上重新分析时：

- 相同 `packageId` 保留现有录制数据。
- 不同 `packageId` 先把整个旧包移动到同级 `out/v02/history/spec_292-<旧指纹>`，再写新包。

### 2.5 录制与补测

1. 打开录制游戏并完成登录，同时打开看板。
1. 在看板输入用例名称并开始录制，再进入目标模板关卡；普通 Spin、FreeSpin、Bonus 和退出重进按实际测试流程执行。已在关卡内开始录制时，只能记录此后的执行，补录进房需要退出再进入。
1. 用“标记用例”切换用例，以会话、用例筛选覆盖计数；Spin 筛选用于执行轨迹。
1. 从未覆盖清单打开条件、分支臂与源码，补测后检查覆盖变化。“新增命中”表示最近接收批次首次带来的分支臂命中，不是整个会话相对历史的增量。
1. 停止录制后检查采集状态、未确认批次和日志缺口，再导出报告。
控制命令通过录制页面轮询领取，接口接收成功表示命令已经排队。执行失败会返回到看板状态。多个浏览器同时连接时，命令由一个录制器领取；需要确定目标页面时只保留该页面的录制连接。

#### 2.5.1 单次响应注入

- 看板的“导入注入数据”接受一个完整的服务端响应 JSON，导入后可以编辑协议类型与响应内容。使用实际录制得到的完整响应修改目标字段，不应把局部字段对象当成完整响应提交。
- 当前支持 `s2c_spin`、压缩 Spin、`s2c_enter_subject_room`、`s2c_slot_param` 对应协议。注入只替换下一次匹配请求的响应，不直接执行响应处理函数，也不会生成请求。协议、房间、会话或用例不匹配时保持待命；停止录制会清除待命注入。同一时刻只能有一个待命注入。
- fixture 真正被消费后，该用例才标为“注入”；仅导入、排队不会改变自然测试的标记。普通请求与推送响应均有录制入口，替换响应只回调一次。
- `scripts/test-game-injection.js` 导出的 `recordInjection(page, {output, specDir})` 是 292 红色 FreeSpin/重触发的固定人工样例，要求已有登录后的 292 页面与自然响应日志。其产物 `game-292-injection-fixtures.json` 保存来源和三份响应；手工导入时取单份 `response` 对象，不是整个集合。样例只验证客户端流程，使用前需核对当前会话的余额等同步字段。具体实测限制见 VALIDATION.md。
- 开发者也可使用现有全局入口：
```javascript
__wtcRecorder.start({ caseId: 'base-spin' });
__wtcRecorder.scene('free-spin-retrigger');
__wtcRecorder.inject(fullResponse, { requestType: 'c2s_spin', subjectId: currentSubjectId });
__wtcRecorder.status();
__wtcRecorder.flush();
__wtcRecorder.stop();
__wtcRecorder.export({ download: true });
```

- 最后一项导出浏览器本地保留的事件、快照和未确认批次，可用于采集服务不可达时保留当前证据。
- 默认为实时摘要模式：浏览器每 `500ms` 上报发生变化的覆盖计数和图谱节点状态，看板会实时更新；摘要只在服务内存中合并，不写入持续增长的中间批次文件。停止时才写入完整汇总，因此覆盖率、分支命中、用例和注入标记可在重启后恢复，时间线默认为空。需要完整调用、异步和协议时间线时，在开始录制前设置 `window.__wtcAnalysisConfig.traceDetail = true`；此详尽模式才启用 `maxEvents: 100000`、每 `500ms` 上报、每批最多 `10000` 个事件的有界队列。
- 录制构建会自动将源码中的 `let`、`const` 转换为 ES5，保持块作用域、循环闭包和常量写入限制，无需为提取修改业务源码。标准覆盖坐标仍基于原始源码，转换辅助代码不进入分母；其他不支持的语法继续在 ES5 校验时报错。
### 2.6 图谱和覆盖口径

- 看板默认以源码中可识别的进房、Spin、FreeSpin、Bonus、结算入口分组，并保留关卡组件、公共代码和外部边界。展开节点后查看类、方法、控制流和分支。图中关系来自静态提取；分组名称与布局本身不代表已证明的运行顺序，实际执行顺序看时间线。
- 图谱每页最多 250 个节点，长条件在图中缩略、详情中保留原文。详尽模式下时间线每页 500 个事件，通过游标加载更早批次；在线单次查询最多返回 10,000 条，完整总数与当前页分别展示。服务只缓存最近最多 10,000 条 / 16 MiB 事件，原始批次保留在磁盘。事件详情保留关联的会话、用例、Spin、调用、异步任务、房间和状态摘要。
| 数据 | 计量方式与边界 |
| --- | --- |
| 分支、函数、语句、行 | Istanbul 标准分母；关卡自有与相关公共代码分别报告，未加载项目保持零命中 |
| 补充决策 | 短路、switch 选择/穿透/无匹配、循环与异常等语义计数独立展示，不计入标准分支率 |
| 关卡归属 | 生命周期建立上下文，并传播到已适配的 Flow、Action、事件、定时和动画回调；无法归属的公共命中单列 |
| 迟到回调 | 保留事件产生时绑定的原会话、用例和 Spin，不随当前筛选或新用例重分配 |
| 状态摘要 | 记录成员赋值表达式的返回值摘要；对象保留类型，字符串有限长；`++`、`--`、`delete` 不录写入值，但仍有标准计量和所在函数轨迹 |
| 异步证据 | 排队、执行、完成及监听注册/触发分别记录，保留任务或监听身份与调用关联 |
| 可靠采集 | 覆盖率使用累计快照，顺序日志使用有界缓冲、确认、重试与批次去重；采集服务启动时恢复已落盘批次 |

- 标准分支率不等于全部执行路径、条件组合覆盖或 MC/DC。未知归属、未解析项、日志缺口与未确认批次不能解释成“未发生”或“已完整验证”。帧与内存采样用于观察录制开销，源码测试夹具的性能数据不等同于完整游戏性能。

### 2.8 规格包结构与兼容

- 本节描述独立 CLI 目录布局。统一服务在 `out/lab/registry.json` 保存当前发布指针、任务及变更记录，在受管理的 `packages/` 下保存每关当前包；它不自动收纳或删除既有 `out/v02` 数据。
```
out/v02/spec_292/
  static/
    manifest.json           版本、来源、指纹、范围、完整性与标注摘要
    graph.json              节点、关系、源码坐标与人工说明
    coverage.json           Istanbul 零计数与全部固定分母
    scope.json              自有、公共与边界范围
    unresolved.json         未解析位置和原因
    branches.json           补充语义决策全集
    classes.json            类、全部函数与源码归属
    ...                     保留 config/assembly/state-contract 等既有槽位
  sources/<仓库相对路径>     完整源码快照
  slices/<类>/<方法>.src.js  既有方法切片
  targets.json              录制构建清单和指纹
  recording/                独立录制构建产物
  traces/batches/           持久化、可恢复的采集批次
```

- `schema/spec-package-v02.schema.json` 是新工具链结构契约，旧 `schema/spec-package.schema.json` 与 `golden/spec_292` 保留 0.1 子集样例。0.1 包可以只读查看类、方法和分支规格，但不能用于新口径录制与覆盖率；其旧 JSONL 不会换算为 Istanbul 百分比。重新分析得到 0.2 包后才开始新的覆盖采集。
- Golden 是代表性人工样例，不是完整分母。新分析结果的对应事实必须保留这些样例约束，并通过全量 AST、图节点和源码映射校验。
