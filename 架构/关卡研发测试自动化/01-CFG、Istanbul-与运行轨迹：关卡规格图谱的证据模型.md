## 二、CFG：把函数内部结构变成可验证的路径

CFG（Control Flow Graph，控制流图）是函数内部可能执行路线的“路网图”。AST 表达代码长什么样、谁包含谁；CFG 关注执行下一步可能去哪里。它是规格提取的产物，与调用图、组件装配、继承和状态读写关系一起组成关卡规格图。

节点表示入口、语句、条件或出口，边表示可能的控制转移。普通语句顺序相连；if 从条件分出真、假两路；循环体回到条件并保留退出路径；switch 区分选择与穿透；return 指向函数出口，throw 指向可识别的异常处理点或出口。条件和循环的图例见第七节。

### 2.1 生成方式

- 提取器先定位指定模板与风格使用的源码、继承和公共依赖，用 Acorn 与 acorn-walk 解析 AST，再应用 .extend、prototype、组件配置、Action 注册、Process 数组和 SlotFlow 等项目规则。选定函数内部按语句顺序建立控制边，并为条件、循环、switch 和控制跳转增加连接。嵌套三元与短路表达式挂接为决策节点，当前不声称生成完整的表达式级 CFG。
- 节点保留仓库相对路径、源码位置和身份，图上看到的条件可以回到源文件。跨函数调用另用调用关系连接，异步登记与执行也不能仅靠一条普通控制边推断。此过程按规则自动完成，指定新关卡时复用同一套提取器，无需 AI 为每关重新解释一遍代码。
```javascript
function settle(result) {
  if (result.isFreeSpin) return playFreeSpin(result);
  return settleBaseGame(result);
}
```

- 上例会形成“进入 settle → 判断 isFreeSpin → FreeSpin 结算或基础游戏结算 → 函数出口”。测试人员可以直接看到该条件的两个候选方向，点击节点查看源码与所属流程。即使只测过 FreeSpin，基础游戏结算节点仍留在图中；后续覆盖叠加显示它是否命中，详细轨迹则显示某一次运行实际走过的方向。
### 2.2 在设计中的作用

- CFG 提供约定分析范围内可核查的结构与候选路径，不断言某次游戏已经走过，也不证明所有画出的路径都可达。“简化”意味着保留明确的结构和控制关系，同时披露无法可靠确定的动态调用、回调目标、带标签跳转，以及 finally 中复杂提前退出等解析缺口。
- 当前工具没有符号执行、完整变量值传播或路径可达性证明。测试使用图谱寻找条件与补测方向；运行证据可以证明某次命中发生过，但不能自动消除该动态结构的全部静态缺口。没有对应标准计量坐标的图节点也不能直接解释为 0% 覆盖。
## 三、Istanbul：把测试运行转成稳定的命中事实

- Istanbul 是 JavaScript 的覆盖率工具体系。本方案使用 istanbul-lib-instrument 生成插桩与映射，使用 istanbul-lib-coverage 汇总指标。原理是在语句、函数入口和分支臂处插入累加计数，执行即递增；它不需要先消费我们的 CFG，也不理解 Spin 或 Bonus 的玩法含义。
- 它在提取阶段就被调用，为全部选定文件生成 statementMap、fnMap、branchMap 与零计数；录制构建再为实际执行源码加入相同口径的计数。浏览器保存 s、f、b 计数，录制运行时读取累计快照上报，服务端据映射归还源码位置。行覆盖率从语句位置与计数派生。主文档第三章保留了 settle 函数插桩前后的示例。
- 这项设计让不同用例、测试者与测试时机的结果具有同一分母。未加载文件仍为零覆盖，未执行方法仍在函数分母中；函数、语句、行和分支覆盖分别计算，跨文件通过合并已覆盖项与总项汇总，不平均百分比。
- 分支按“臂”计量：if 有真、假两个方向，只执行 FreeSpin 的真分支，即使到达条件一百次，该 if 仍是 1/2 = 50%；执行过另一个方向后才是 2/2 = 100%。重复命中只增加次数，不再提高这一项的覆盖率。
### 计量口径如何进入规格图

- 规格包把 Istanbul 的文件、计数编号与源码位置关联到图节点的 coverageRef。标准覆盖分母来自映射，不能数 CFG 节点或边代替；单个臂按是否命中着色，包含多个臂的节点可显示部分覆盖。没有可靠映射或尚未解析的关系单独标明。公共代码与关卡自有代码分别报告。
- 构建先建立原始源码覆盖口径，再做必要兼容转换与轨迹插桩；转换辅助代码、探针代码不增加待测分母。同一来源、会话和用例的累计快照按计数最大值接纳，避免重复和乱序上报重复累计；不同有效用例再汇总。只有规格身份一致的数据参与当前覆盖，旧版本迟到数据不混入新版本。
- Istanbul 给出稳定的代码命中事实。逻辑表达式的标准分支计数主要反映操作数求值，switch 的 case 计数可能来自直接选择或穿透；不能由此直接推断所有条件真值组合或精确执行路径。短路选择、switch 穿透和无匹配、循环、异常流转由语义探针提供补充观察，单列展示，不改写标准分支率。
- 100% 分支覆盖仍不等于全部路径组合覆盖、条件组合覆盖或 MC/DC，也不能证明判奖、动画或异步时序正确。覆盖率用于定位代码测试缺口，玩法预期与正确性需要结合断言和人工验收。
## 四、轨迹探针：为实际执行补上顺序和上下文

- 轨迹探针是录制构建后加的诊断代码，属于运行时录制。它记录函数进入与退出、决策结果、状态写入，以及异步任务排队、回调开始与完成。节点 ID 连接源码和规格图，callId 与父调用关联同步调用，taskId 与 executionId 关联异步登记和多次执行。事件带序号、时间和可用时的帧号，帮助区分“登记了任务”和“任务真的执行”。
- 关卡生命周期入口建立上下文，定时器、动画帧、Cocos 调度和事件、Flow、Action、协议回调等适配器在注册时复制它，在执行时恢复它。上下文包含会话、用例、Spin 和房间身份；事件产生时固定这些值，迟到回调在允许收尾期间仍属于原用例。超过收尾边界会受到限制，并记录截断等质量信号。
- 这套上下文管理同时服务于 Istanbul 计数与轨迹。标准计数在命中时归入当前上下文，无法确认归属的公共命中进入 unknown 桶；不需要先保存详细事件再推算归属。函数入口探针和异步包装仍可参与上下文管理，即使详细日志关闭，正确归属也必须继续工作。
- 默认摘要模式只保留覆盖累计计数、图谱决策命中摘要及用例等元数据，每 500ms 上报变化，停止录制后持久化完整汇总；时间线默认为空。需要过程证据时，在开始录制前将 window.__wtcAnalysisConfig.traceDetail 设为 true。开启后再保存和上报有顺序的函数、决策、状态、异步与协议事件。
- 详细模式使用有界缓冲、批次确认、重试与去重，显式披露溢出、未确认和尾部截断。覆盖快照独立于顺序日志：日志缺一段不能自动判定其中代码未覆盖，也不能把轨迹完整性当成覆盖快照已送达的证明。服务重启能恢复已落盘汇总与详细批次；默认模式未保存的中间过程不承诺恢复。
- 状态探针记录写入后的值摘要，不保存完整对象，也不自动计算完整前后状态差异。函数退出、回调返回只代表这个执行边界结束，不等于整个异步玩法完成。轨迹适合解释某次执行和排查时序，不是可逐帧重放的完整确定性回放。
## 五、测试人员如何使用这套设计

1. 在本地服务人为指定关卡与风格，执行提取。服务固定源码范围、CFG、标准覆盖映射与规格身份；录制构建成功发布后，该关卡才进入看板可选列表。
1. 从玩法流程进入组件、函数与分支，查看解析缺口与未覆盖项，准备进房、普通 Spin、FreeSpin、Bonus 或结算用例。CFG 提供候选条件，不能据布局直接断言实际执行顺序。
1. 打开游戏测试页面并在看板选中它；日常覆盖使用默认摘要模式，需要时预先开启详细轨迹。开始录制、标记用例并操作；也可导入匹配协议类型的一次性响应，真正消费后区分自然与注入用例。
1. 观察实时覆盖，停止后确认收尾与上报完成。对只命中一臂的条件准备相反状态或协议数据；详细模式下结合时间线查看是条件不满足、回调尚未执行还是发生了异常。再录制补测，检查当前版本累计覆盖中新增的命中项。
1. 源码、配置或分析输入变化后更新规格与构建。新录制构建成功发布且可访问后，通知运行中的页面重新加载并校验实际身份；构建失败维持原发布版本，旧数据不进入新版本统计。当前覆盖始终对应最新发布规格，变更记录与当前百分比分开保存。
## 六、阅读结果时的边界

- CFG 回答静态可能怎么走，Istanbul 回答哪些标准代码项命中过，轨迹回答某次执行的顺序和上下文。详细轨迹可按需开启；关闭它不影响标准覆盖率的计量口径，但无法事后补出未录下的完整时间线。

- 解析缺口、unknown 归属、轨迹丢失、未确认快照和版本不匹配分别报告，不能由一个百分比掩盖，也不能把未知直接涂成未覆盖。工具的目标是让结论回到源码、用例和执行证据，为补测提供依据，不承诺穷尽所有动态路径或替代完整玩法验收。
## 七、图例与数据示例

### 7.1 CFG：同一段源码，语法树与路网图各表达什么

- AST 更像代码的语法目录，描述“谁包着谁”。例如下面的 if 包含一个条件、一个成立分支和一个不成立分支：
```javascript
function settle(win) {
  if (win > 0) {
    return win;
  } else {
    return 0;
  }
}
```

- CFG 关心下一步可能去哪里。条件节点分出两条路，各自执行 return 后到达函数出口；本次测试没有发生的那条路也会保留。

- 普通顺序语句是 A → B → C；if 分出真、假边；switch 表示 case、default 与穿透；return 指向函数出口，throw 指向可识别的 catch 或异常出口。这里只展示约定范围内的控制关系，不为动态调用目标和复杂异常语义编造确定路径。
- 由此区分几个容易混淆的产物：AST 描述语法嵌套；CFG 描述函数内候选路线；调用图描述函数间关系；运行轨迹描述某一次测试的实际顺序；标准覆盖率描述可计量代码项的命中情况，并非整条路径的组合覆盖率。

### 7.3 轨迹探针：一次 FreeSpin 命中的证据

```javascript
if (isFreeSpin && winAmount > 0) {
  awardBonus();
}
```

- 以下为简化后的 decision 事件示例，字段名对应当前事件结构，值为示意。关卡与 packageId 由所属会话和上报数据关联，避免误以为每条事件都重复携带完整规格。

{
